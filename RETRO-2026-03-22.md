# Retrospective — 2026-03-22: Mobile Bug Sprint

## Bugs Fixed Today

1. **Mobile blank pages (CSS)**: `.reader-columns` had `max-width: 100vw` and `overflow: hidden` in mobile media query, clipping multi-column content beyond first page. Parent already clips.

2. **Left text clipping (GAP mismatch)**: `GAP = 60` hardcoded in Reader.tsx and SplitReader.tsx, but mobile CSS had `column-gap: 40px`. TranslateX overshot by 20px per page turn. Fixed by reading computed `column-gap` from DOM.

3. **Compare mode too cramped on mobile**: SplitReader showed two columns side-by-side on narrow phone screens. Changed to show alternate edition full-width using regular Reader.

4. **Reading position lost on reload (race condition)**: App initialized `currentPage = 0`, Reader reported `onPageChange(0, totalPages)` before restoring saved position, and `useReadingPosition` saved page 0 over the real position. Fixed by initializing from saved position and delaying save enable.

## Root Cause Patterns

### Pattern 1: Hardcoded values that diverge from CSS
The `GAP = 60` constant matched desktop CSS but not mobile. Anytime a JS constant mirrors a CSS value, we're one media query away from a mismatch.

**Rule going forward**: Never hardcode CSS-derived values in JS. Read computed styles from the DOM. If perf matters, cache them and invalidate on resize.

### Pattern 2: Race conditions in React effect ordering
The position save bug happened because three effects (recalcPages, onPageChange, initialPage restore) fired in an order that overwrote saved state before restoration completed.

**Rule going forward**: State that needs to survive reloads should be initialized from storage in `useState()`, not restored in a later `useEffect`. The initial render should be correct, not fixed up after.

### Pattern 3: Desktop-only testing
All these bugs were mobile-specific. The desktop app works well. Mobile was untested.

**Rule going forward**: After any change to Reader/SplitReader/pagination, test on mobile viewport before deploying. Even a Chrome DevTools mobile resize catches these.

### Pattern 4: CSS properties fighting each other
The mobile media query added `overflow: hidden` and `max-width: 100vw` to `.reader-columns`, not realizing the parent `.reader-paginated` already handled clipping. Double-clipping caused blank pages.

**Rule going forward**: Before adding overflow/clipping CSS, check the parent chain. Only ONE element in the hierarchy should clip.

## Still Broken

- **Chat on mobile (production)**: Works on desktop via Vite dev proxy. Production Cloudflare Workers config doesn't serve the `/api/chat` endpoint. Needs either Pages deploy or Worker entry point, plus `ANTHROPIC_API_KEY` secret.
- **Cross-device position sync**: Requires Supabase (Phase 1b). Currently localStorage only.
- **Page count doesn't adapt to Compare mode height**: The GAP fix improved accuracy but the container height may not change between Read/Compare modes on mobile.

## What the CEO Should Do Differently

1. **Self-test on mobile before deploying.** Use Playwright or Chrome DevTools mobile viewport.
2. **Audit all JS constants that mirror CSS values.** Replace with computed style reads.
3. **Test state persistence on every reload path** — initial load, chapter change, book change, reload.
4. **Don't add CSS overrides without checking the parent chain** for existing overflow/clipping.
